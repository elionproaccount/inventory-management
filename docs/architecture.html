Factory Inventory Management System

A full-stack demo: a Vue 3 single-page dashboard backed by a FastAPI service that serves in-memory data loaded from JSON files. There is no database.

System architecture

Three layers, two processes. The browser app talks to the API over HTTP/JSON.

Data flow

What happens when a user changes a filter on any page.

  1. Filter change. The user picks a period, warehouse, category or order status in FilterBar. The values live in the shared useFilters composable, so every view sees them.
  2. Request built. The view calls getCurrentFilters() and passes the result to api.js, which adds only the non-all values as query parameters.
  3. HTTP call. Axios sends GET http://localhost:8001/api/.... The browser is allowed through by the permissive CORS middleware.
  4. In-memory filtering. The route handler runs apply_filters (warehouse, category, status) and filter_by_month (a month such as 2025-03 or a quarter such as Q1-2025) over lists loaded from JSON.
  5. Validation. FastAPI checks the result against the endpoint's Pydantic response_model and serializes it to JSON.
  6. Reactive update. The view stores the response in a ref (for example allOrders or inventoryItems). Computed properties derive the totals, chart series and tables, and Vue re-renders.

Observations

Things worth knowing before changing the code.

Client calls endpoints the server does not define. api.js calls /tasks (list, create, delete, toggle) and /purchase-orders (create, get by backlog item), but main.py has no such routes. The PurchaseOrder models exist, and purchase_orders.json is read, but nothing writes to it.

Characteristics

  • Data is read-only and loaded once at startup; restarting reloads the files.
  • Quarter and month logic is duplicated: QUARTER_MAP and the long if chain in the quarterly report.
  • The API base URL is hard-coded in api.js, and CORS allows every origin. Both suit local development only.
  • No authentication on the server; useAuth is client-side only.
